# Overriding nullability (PostgreSQL)

TypeSQL infers whether each result column can be `null`. When the inference is wrong, add `!` or `?` to the end of a quoted column alias to override it:

- `"name!"` makes the column non-nullable.
- `"name?"` makes the column nullable.

For example, TypeSQL can't tell that `regexp_match` always finds a match when the `WHERE` clause already requires one, so it infers `domain: string | null`. `!` tells it otherwise:

```sql
SELECT
    id AS "id?",
    (regexp_match(email, '@(.*)$'))[1] AS "domain!"
FROM users
WHERE email LIKE '%@%'
```

```ts
export type SelectUsersResult = {
	id: number | null;
	domain: string;
}
```

The suffix is removed from the generated field name. This is an assertion, not a check: if a column marked `!` returns `null`, the value at runtime is `null` and won't match its type.

Only PostgreSQL is supported.

A quoted alias that already ends in `!` or `?` now changes nullability and loses the suffix in the field name. For example, `SELECT id AS "id?"` now generates `id: number | null`, where it used to generate `"id?": number`. A real column whose name ends in `!` or `?`, selected without an alias, is not affected.

## Where the suffix applies

The override applies to the select list where you write the alias. A bare alias works too: `SELECT email "email!"`.

In a `UNION`, the first `SELECT` names the result columns, so a suffix there overrides the whole column. A suffix on a later `SELECT` affects only that branch.

The suffix also works in `INSERT`, `UPDATE` and `DELETE ... RETURNING`, and in CTE or subquery column lists such as `WITH t("total!") AS (...)`.

A scalar subquery is nullable because it can return no row, even with a suffix inside it. Put the suffix on the outer alias instead: `(SELECT max(total) FROM orders) AS "max_total!"`.

## CTEs and subqueries

PostgreSQL keeps the suffix as part of the column's name. An outer query must reference it with the suffix, in quotes:

```sql
WITH t AS (SELECT value AS "value!" FROM mytable1)
SELECT t."value!" FROM t   -- field: value: number
```

`SELECT t.value FROM t` is an error in PostgreSQL, because no column named `value` exists.

The outer query then infers nullability as usual. A `LEFT JOIN` can make the column nullable again, and `WHERE ... IS NOT NULL` can make it non-nullable. To force the final type, add a suffix to the outer alias as well.

Names inside JSON keep the suffix. `json_agg(t)` and `row_to_json(t)` use PostgreSQL's column names, so the key is `"value!"`. The same goes for the column names accepted by a [dynamic ORDER BY](orderBy_limit.md).

## Limitations

- Column lists on a table alias (`FROM users AS u("id!")`) are not supported. The suffix is ignored and stays in the field name.
- `CAST(t."value!" AS text)` over a suffixed CTE or subquery column keeps the suffix in the field name, and is nullable. Use `t."value!"::text`, or alias the cast: `CAST(t."value!" AS text) AS "value!"`.
- The nested types generated by [`-- @nested`](nested-query-result.md) don't use the override. Only the flat result type does.
